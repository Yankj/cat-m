## 本轮方案采用的工程方向

- 保留 conversation-first + 侧栏 + 原生返回；今天 / 聊聊 / 我们家作为内容分区，不强制底部三栏。该实现细节仍可在交互评审中调整。
- 家庭、成员、目标、计划、事项、观察、记忆分别建模；计划不等于任务，观察不等于事实，模型推断不等于确认。
- 保留一个原生宿主和模块化 Supabase 后端、一个 Postgres；Worker 作为后台执行角色，复用资源，不新增微服务。
- 稳定 ID + revision + command receipt + outbox/lease/generation；卡片点击、流结束、APNs 接受不代表实际完成。
- 以现有 agent-memory 渐进扩展为统一用户事实面，复用 foundation 的版本与安全机制；不继续建设第三套记忆权威。
- 先修初始化失败缓存、提醒 claim/cancel/write 故障、内容日志、延迟观测、记忆 CAS，再扩大自动化。
- 沿用现有模型/预算策略；本轮没有模型切换、付费后备或实际模型调用。

## 待确认，不默认当作用户决定

首发具体年龄段；单成人内测还是首期多照护者；敏感观察的共享权限；原媒体 TTL；自动保存授权；主动建议频率和安静时段；真实模型与设备验收范围；签名/APNs/runner/隔离测试资源；公开商店或受控内测路径。

技术方案建议先小学阶段、单成人、口述转文字、每天最多一条非紧急主动建议，均是可评审默认值。性能与工期数字是提议，不是实测或承诺。
