# cat 家庭成长助理 · 后续产品规划 v1（草案，待用户确认）

> 依据：[positioning-v1.md](positioning-v1.md)（2026-10-23 用户已确认）、[decisions.md](decisions.md)、api-v1.md、docs/family-product-plan@6621ee9a。
> 原则：**可靠比聪明重要，克制比热闹重要。** 每一阶段只加一件让妈妈更省心的事，做稳再往下走。
> 本文的时间、指标阈值都是提议，不是承诺；标「🔶决策」的需要用户拍板。

## 0. 贯穿所有阶段的底线

- **真实端到端验收**：每个版本都用真实账号、真实后端、真实设备或指定模拟器（BE5C）走完整链路；mock 和截图不能替代验收。
- **两个零**：错误的家庭信息写入 = 0；越权访问（看到或改到别人家数据）= 0。出现一次就停下发布，先修。
- **确认后才改**：凡是写入日程、档案、提醒的动作，都先出确认卡；未确认不说「已安排」。
- **克制提醒**：每天最多 1–2 条，21:00–08:00 安静，每条提醒都说明「为什么现在提醒」。
- **记忆可看、可改、可删**：记忆被使用时标出来源；删除要真删（tombstone + 清理代次）。
- **首轮不做**：多人共享、实时语音通话、自动报名或缴费。后面阶段要放开任何一项，都单独立项、单独确认。
- 生产库、schema、部署、合 main、打 tag，都需要用户确认。

## 2. v0.5 · iPhone 真机验收（单成人自用）

- **用户价值**：妈妈在自己手机上真的用起来：随手拍一张通知，第二天早上「今天」就排好了，到点提醒、不漏也不打扰。
- **范围**：真机安装（原地覆盖安装，不卸载）；APNs 推送真实到达；拍照、文字两种入口；今天 / 我们家 / 对话记录三个页面；连续 7 天自用。
- **非目标**：新功能、语音输入、成长小结、任何分享。
- **验收标准**：
  - 真机完成 10 条真实家校通知的「拍照 → 确认卡 → 今天 → 提醒」全链路；
  - 错误家庭信息 0、越权 0；未确认事项 0 条被当成「已安排」；
  - 安静时段内推送 0 条；单日提醒不超过 2 条；
  - 断网或杀进程后重开，草稿、确认状态不丢不重。
- **指标**：通知识别字段正确率（时间、孩子、要带什么、截止）≥ 95%（以人工核对为准）；需要改字段的确认卡比例；7 天里实际被提醒救回的事项数。
- **风险**：签名、APNs 证书、推送延迟；手机相册里的通知截图质量差。
- **依赖**：签名与 APNs 配置；生产部署（三角执行，用户批准）。
- **🔶决策**：真机验收的样本范围（用哪些真实通知）；是否进入 v0.6 小范围内测。

## 3. v0.6 · 变动一键处理 + 语音随手丢

- **用户价值**：调课、临时停课时不用自己挨个改；路上说一句话也能交代事情。
- **范围**：
  - 变动识别：新通知与已有日程冲突时，列出受影响的接送、提醒，问「要一起改吗」，一次确认批量改；可撤销。
  - 语音输入：按住说话 → 转文字 → 走同一条确认卡链路（不是实时通话）。
  - 「待确认」区：拿不准的日期、班级统一放这里，宁可多问一句。
- **非目标**：实时语音对话、自动替用户回复老师或家长群。
- **验收**：10 组真实调课场景，连锁影响列全且无误改；撤销后状态完全复原；语音 20 条真实口述，字段确认后正确率 100%（错的必须在确认卡上被改掉，而不是写进去）。
- **指标**：变动处理平均点击数；被撤销的批量修改比例（越低越好）。
- **风险**：连锁修改误伤；口音、环境噪声。
- **依赖**：v0.5 稳定；修订号 CAS 与操作 id 已在 v0.1 打好基础。
- **🔶决策**：语音原始音频保留时长（建议转写后即删）。

## 4. v0.7 · 小范围内测（5–10 户，仍单成人）

- **用户价值**：验证不是只有我们自己觉得好用。
- **范围**：受控内测分发（TestFlight 或企业内测，🔶决策）；新用户引导：3 分钟建好「我们家」；问题反馈入口；隐私说明与数据导出、整户删除。
- **非目标**：公开上架、付费、增长投放、多人共享。
- **验收**：每户数据严格隔离（跨户越权测试全部拒绝）；整户删除后服务端可查数据为 0；引导完成率 ≥ 80%。
- **指标**：第 2 周仍在用的户数（目标 ≥ 60%）；每户每周丢进来的事项数；用户主动说「这条提醒救了我」的次数；关掉提醒的比例。
- **风险**：真实用户的通知格式远比样本杂；单户出错的信任代价很高。
- **依赖**：内测分发通道；隐私文案；运营上能逐户跟进。
- **🔶决策**：内测人选和人数；是否收集匿名使用数据，收集到什么粒度。

## 5. v0.8 · 成长陪伴进入（第二层，轻）

成长陪伴只在妈妈已经信任「不漏不错」之后才出现，并且默认低存在感。

- **用户价值**：日常丢进来的点滴，不用额外整理，就慢慢变成看得见的成长。
- **范围**：
  - 顺手沉淀：确认过的事项和随口记录里，标出「观察」（如「这周三次主动练琴」），只来自用户给的信息；
  - 每周一份简短小结（周日晚 20:00 前，可关），三五行，附来源；
  - 「我们家」里按孩子看观察时间线，可改可删。
- **非目标**：发育诊断、评分排名、焦虑营销、育儿课程推销、自动生成「成长规划」长报告。
- **验收**：小结中每一句都能点回来源；没有来源的结论 0 条；敏感观察（健康、情绪）默认不出现在小结，除非用户开启。
- **指标**：小结打开率；被用户删掉或改掉的观察比例；因为小结而关掉通知的比例（警戒线）。
- **风险**：说得过多显得说教；记错一条孩子的事伤害远大于漏一条。
- **🔶决策**：小结频率与默认开关；敏感类别的范围；要不要给轻建议（建议默认只描述、不建议）。

## 6. v0.9 · 多人共享进入（第二照护者）

- **用户价值**：爸爸或老人接送时，能看到今天谁去哪、带什么，不用妈妈再转述——减少的是妈妈的心理负担，不是把负担转给别人。
- **范围**：
  - 邀请一位照护者，角色分级：只看今天 / 可确认事项 / 管理员（妈妈）；
  - 指派：「这次接送交给爸爸」，对方确认后才算接手；
  - 敏感观察与成长记录默认仅创建者可见；
  - 审计：谁改了什么、何时，可在事项上看到。
- **非目标**：家长群式聊天、班级群同步、老师端、多家庭互联。
- **验收**：RLS 从单成人扩展为家庭成员模型，全量越权矩阵测试（角色 × 资源 × 动作）0 失败；撤销邀请后对方立即失去访问；两人同时改同一事项无丢失（CAS 冲突有明确提示）。
- **指标**：被接手的事项比例；妈妈端每周需手动转述的次数（自述）。
- **风险**：权限模型复杂度陡增；家庭内部隐私边界。
- **依赖**：schema 与 RLS 迁移（需用户批准，生产部署走三角）；独立安全复核（NoBug）。
- **🔶决策**：首期是否开放；角色定义；敏感信息共享规则。

## 7. v1.0 · 稳定公开版

- **用户价值**：一个可以放心推荐给其他妈妈的家庭事务大脑。
- **范围**：v0.5–v0.9 的能力打磨；可靠性（推送到达、离线、恢复）；无障碍与深色模式；公开上架准备（隐私标签、审核材料）。
- **非目标**：自动报名缴费、开放平台、安卓（另立项评估）。
- **验收**：连续 30 天内测无错误家庭信息、无越权；崩溃率 < 0.5%；提醒按时到达率 ≥ 99%（±1 分钟）。
- **指标**：第 4 周留存；每周省下的「惦记」事项数；NPS；单户月成本（模型 + 推送 + 存储）。
- **🔶决策**：是否上架、上架地区；定价与是否收费；预算。

## 8. 1.0 之后（方向，不承诺）

按「省心程度 / 出错代价」排序，逐个立项：

1. **只读日历同步**：把确认过的事项同步到系统日历（单向，不回写）。
2. **学期级规划**：开学、假期、考试周的事务批量预排，仍走确认。
3. **更多来源**：转发邮件、分享扩展直接丢文件。
4. **外部动作（最后考虑）**：报名、缴费只做到「准备好信息 + 打开对应页面」，付款永远由用户自己点；自动支付不在计划内，除非用户另行决定。
5. **实时语音**：只在明确有需求且隐私方案成熟后评估。

## 10. 节奏

每个版本结束都停下来，由用户验收后再继续；任何一版出现错误家庭信息或越权，回到上一版修复，不带病前进。
