# Catpaw 聊天视觉与微交互规格

本规格用于把参考图的细节转化为 Catpaw-m 可验收的设计，不表示功能已实现或已通过真机测试。当前修复版保持已锁定范围；完整视觉升级进入下一版。Mac 离线时，可继续在云端完成规格、状态样例和测试设计，iOS 实机交互与性能验收须待可用设备。

## 参考图可以确认什么

- 画面采用接近纯黑的页面背景、较亮一层的深灰助手气泡、浅色正文。用户气泡使用高明度黄色与深色字，形成单一强调色。
- 助手长消息靠左，圆角较大；用户短消息靠右，接近胶囊形。状态小字在气泡外，与正文分层。
- 顶部左右是圆形线性图标按钮；底部输入框是深色胶囊，左侧加号，右侧麦克风。图标端点圆润、视觉分量接近。
- 等待提示在左下：深灰小气泡内有三个圆点，左下有圆点式尾部。它与普通助手消息同属一套气泡语言。
- 顶部有独立角色形象与名称层，消息在其后方延伸。可学习层级分离，不复制该角色、配饰或造型，不替换已批准的 Catpaw 标识。
- 单张图不能确认圆点是否跳动、动画顺序、触觉反馈、图标命中区、实际字号或 pt 尺寸。以下时间、颜色和尺寸均为设计提案，不是对截图的测量，也不是 Apple 强制参数。

## 视觉规则与建议值

| 项目 | Catpaw 提案 | 验收要点 |
| --- | --- | --- |
| 深色层级 | 页面 #080808；助手气泡 #242424；输入层 #151515；正文 #F5F5F5；次级字 #A3A3A3 | 浅色模式另设语义色；占位符与错误信息同样实测对比度 |
| 强调色 | 沿用 Catpaw 已批准品牌色；仅用于用户气泡或主要动作 | 不因参考图擅自改为黄色；状态不能只靠颜色 |
| 消息形状 | 连续圆角约 22–26 pt；水平内边距 14–16 pt，垂直 10–12 pt；短句可自然接近胶囊 | 多行气泡保持圆角，不把长文做成巨型椭圆；中文不裁切 |
| 排版与宽度 | 正文使用系统 body；气泡最大宽度初始约容器 84%；左右边距 16 pt | 大字级别可放宽气泡；iPad 限制行长；长链接可断行；不照搬截图的字号比例 |
| 图标 | 同一符号体系、相近字重；可见尺寸约 20–24 pt，圆端点 | 按光学重心校正，不仅看几何包围盒；电话、加号、麦克风、发送、停止不能忽粗忽细 |
| 触控区域 | 每个关键控件至少 44×44 pt；相邻区域不重叠 | 44 pt 是本项目采用的目标；不能把 22 pt 图形当作命中区 |
| 思考气泡 | 约 58–64×32–36 pt；三个 5–6 pt 圆点、4–5 pt 间距；尾部可做 Catpaw 自有简化轮廓 | 尾部保留布局空间、不可被裁切；轮廓不冒充品牌标识；点不是三个可聚焦按钮 |

Apple HIG 建议采用清晰层级、支持 Dynamic Type，并检查文字与图标的对比度；其可访问性指导列出 iOS/iPadOS 的 44×44 pt 默认控件尺寸。本项目将其作为关键交互的最低目标，并对正文采用至少 4.5:1 的验收目标，不机械套用参考图的暗灰。[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

## 状态和动画验收矩阵

状态由真实事件驱动。消息传输、回复生成、工具执行、连接情况是不同维度，不应用一个 loading 布尔值替代。矩阵里的顺序是常见路径，不是必须逐个演出的阶段。

| 状态 | 进入证据与可见反馈 | 动画提案 | 退出与核心验收 |
| --- | --- | --- | --- |
| composing 编辑 | 本地草稿；有可发送内容才启用发送；中文输入法仍在组词时不误提交 | 输入控件遵循系统行为 | 草稿不因断网、切后台或输入法切换丢失；空白不发送 |
| sending 发送中 | 已触发提交、尚无服务端确认；本地气泡显示“发送中” | 按下视觉反馈 60–90 ms 内开始；淡入 120–160 ms | 立即防重复提交；不能显示“已读”；上传与提交分开标注 |
| accepted 已接收 | 服务端确认消息及请求身份 | 文本轻淡切换，0–120 ms；无需强制停留 | 仅说明服务器接收；未有阅读事件就不用“已读”；极速响应可直接进入正文 |
| thinking 等待回复 | 后端明确开始生成或工作；若仅确认接收，文案为“等待回复” | 三点依次亮暗：周期约 1.2 s、相差 140 ms、亮度约 45%–85%；可选位移不超过 2 pt，默认不叠加缩放 | 无首字也不谎称具体思考步骤；停机或断线时不得无限冒充进行中 |
| first token 首段到达 | 第一段可显示内容真实到达 | 同一回复身份、左侧锚点保持；三点 80–120 ms 淡出，容器 160–220 ms 平顺变为正文 | 内容立即可读，不等待整段动画；同一帧无两个重复助手气泡；不可用占位高度造成跳屏 |
| streaming 持续输出 | 连续增量内容到达 | 文本批量刷新约 30–60 ms；不逐字弹跳、不逐字触觉 | 保留稳定消息身份；只有靠近底部才跟随；用户翻旧消息时显示“有新内容”入口 |
| tool running 工具执行 | 工具开始事件及真实可公开名称 | 小型状态行/进度符号；已有正文保持可见；无分母则只用不定进度 | 显示实际动作类别，不用假百分比、假倒计时或虚构推理；工具成功不等于现实目标完成 |
| wait user 等待确认 | 后端发出需要用户决策的明确请求 | 停止三点循环；出现简明说明与明确动作 | “确认”“取消”含具体对象；不倒计时代替授权、不自动确认；焦点可达 |
| reconnecting 重新连接 | 连接中断或恢复流程开始 | 静态连接提示优先；已有正文和草稿保留 | 不写成“任务失败”或“仍在思考”；按请求身份查询真实状态、补齐事件，不自动重做有副作用动作 |
| error 错误 | 后端明确失败，或客户端只能确认传输失败 | 静态图标＋可读原因；可选一次短淡入 | 区分“未发出”“结果未知”“执行失败”；未知结果先核对，禁止盲目重发；允许复制草稿/正文 |
| cancelling / cancelled 取消中／已停止 | 用户发起取消后先“正在停止”；仅确认后“已停止” | 马上停止装饰动画；状态短淡切换 | 中断生成不等于撤销已执行工具；保留部分正文并标明未完成；竞态不覆盖更晚的真实完成结果 |
| complete 完成回复 | 回复终止事件与最终内容一致 | 不必庆祝；状态安静消失或变为完成 | 流结束、工具返回成功、任务真正完成分别记录；缺失终止事件不得猜成功 |

按下反馈、等待指示、首段过渡都是不同动画任务。不得为展示三点而延迟已经到达的内容；建议只在等待超过 150–200 ms 时出现三点，期间保留“发送中／已接收”的真实反馈。网络超时阈值采用协议约定，而非视觉设计的定时器。

## 动效边界与辅助功能

- 动效只解释状态改变。微交互提案：按钮按下缩至 0.97–0.98，释放 120–180 ms；容器尽量不弹。若使用 spring，位移过冲不超过 2 pt、缩放过冲不超过 1%，约 250 ms 内收敛，允许随时中断。不能让整页、长消息或输入框反复弹跳。
- Reduce Motion 开启后：取消位移、缩放、弹簧和循环点动画；静态三点配“等待回复”，状态转换采用直接替换或约 100 ms 淡化。重要状态不依赖动画存在。
- VoiceOver：整个等待气泡是一个状态元素；只在进入等待、需要确认、错误、完成等有意义变化时播报，不逐 token 播报、不播每个圆点、不重复读整条长消息。用户可主动聚焦查看增量正文；输出不抢走输入焦点。
- 大字模式：正文、状态、确认按钮使用可缩放文字；按钮标签允许换行，输入框多行增长到适当上限后内部滚动，不能靠缩小字体解决。列表保留位置，末条消息不被输入框遮挡。
- 高对比与减少透明度：提高边界和次级文字辨识度；模糊背景有不透明替代。错误同时提供形状、文字与可访问性标签；灰度下仍能分辨状态。
- 键盘与安全区：输入栏遵守底部安全区及键盘占位；覆盖硬件键盘、横屏、键盘收起、中文组词及大字模式。发送快捷键不得与输入法确认候选冲突；输入控件周围保留系统手势空间。

Apple 的 Motion 指导强调有目的、简短、可打断的动画；以上具体毫秒和 spring 上限为 Catpaw 提案。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

SwiftUI 提供 Reduce Motion 等环境值，可据系统设置切换表现；官方还建议测试减少透明度、增强对比度和硬件键盘交互。[SwiftUI Reduce Motion](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityreducemotion) · [Apple accessibility testing](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app)

## SwiftUI 实施指导

以下是结构指导，不提供已实现的代码或验收结论。

1. 建立由事件归约得到的消息模型：稳定 message ID、request ID、事件序号、传输状态、生成状态、工具子状态、连接状态、最终性。渲染层不以动画计时器推动业务状态；重复和乱序事件应可安全处理。
2. 气泡壳、正文、思考指示器、消息状态、工具状态行、输入栏分别封装；颜色、间距、图标尺寸和动效参数使用语义 token。同一回复从占位到正文保持身份，允许局部布局过渡；不要对整个消息列表隐式动画。
3. 状态展示有优先级：需要用户动作／错误／连接不确定应可见，不能被普通 thinking 覆盖。保留已收到的正文，不因工具执行清空它。工具是否仍在运行需要查询，不由前端猜测。
4. 只在可见且前台运行时驱动三点动画；界面消失或取消后清理动画与订阅。后台恢复先核对请求结果，再显示当前状态，不补演过去的动画。
5. 将事件接收与 UI 合并刷新分开；首段立即显示，后续短批处理。滚动跟随仅针对原本位于底部的用户；禁用全局几何动画，避免每个 token 重排全列表。
6. 停止按钮有清晰可访问性标签及固定命中区；取消动作绑定当前 request ID。发生停止与完成竞态时按服务端最终事实收敛。后台恢复不能重新提交同一工具调用。
7. 使用合成消息与事件记录做预览、截图和回放测试，不将参考截图、其聊天文本或可识别信息作为仓库资产、测试样例或 issue 附件。

## 当前修复版与下一版

**当前修复版只接纳已锁定范围内、可单独回滚的兼容性修复。** 若现有问题已影响使用，可修命中区不足、气泡裁切、键盘遮挡、重复发送、伪完成标记、状态不确定时重发、Reduce Motion 未尊重等缺陷；任何超出原修复清单的行为变化仍需范围批准。不能用这份提案扩大当前发布承诺。

**下一版视觉打磨候选：** 图标光学统一、气泡 token、Catpaw 自有等待轮廓、同一气泡过渡到首段、流式阅读锚点、工具状态行、完整高对比样式。保持已批准 Catpaw logo；不照搬参考角色或追求截图逐像素复制。

## 最小验收清单

- 快速响应、慢响应、首段后停顿、工具往返、等待确认、明确失败、断网恢复、取消竞态各有合成事件回放；网络快时不强制出现三点。
- accepted 不显示已读；thinking 不显示工具进度；工具成功不自动宣告目标完成；重连后不会重复执行动作。
- 单指连续点发送只生成一个请求；取消可立即操作，无需等动画结束；按下反馈开始时间小于 100 ms，以录屏或性能工具实测。
- Reduce Motion 开关运行中切换有效；VoiceOver 不逐字打断，控件读名准确；增强对比度、灰度、大字号可完成发送和取消。
- 键盘弹出收起、大字模式、横竖屏和安全区变化无裁切；查看旧消息时不会强制滚到最新。
- 后台再进入先对账；未知结果不会伪报成功、失败或擅自重试。稳定身份使同一回复不会因恢复重复出现。
- 云端可验证规格、合成状态和纯逻辑测试；真机触控、VoiceOver、帧率、键盘适配在实际运行并留证后才能标为通过。

## 与当前源码状态协议的只读核对（2026-10-12）

此附录仅核对源码，不代表部署或 UI 验收。依据为 `services/edge/supabase/functions/_shared/core/src/chat-service.mjs` 的 event/runTurn/complete/fail/observe、[原生契约](../../services/edge/docs/NATIVE-HANDOFF.md)，以及 `apps/ios-conversation/Sources/Features/ConversationSessionService.swift:apply/stopObserving` 和 `Sources/Domain/ConversationSessionContracts.swift`。

| 提案状态 | 已有协议证据 | 接线限制 |
|---|---|---|
| accepted | 持久 `turn_started` 携带 request_hash、conversation_revision、grant_epoch；客户端 started 校验这些身份 | 不是已读或生成成功。客户端本地枚举尚无独立 accepted/thinking 维度，不据 running 枚举虚构思考步骤 |
| first token / streaming | `text_delta` 含稳定 message_id；原生递增 sequence，同身份追加正文 | 首段/动画/刷新间隔由展示层提案定义，不新增业务事件或延迟真实正文；本次未实现过渡 |
| tool running | `tool_call/tool_result` 以 call_id 对应；原生仍分别保存调用与结果消息 | 下一版应合并展示同一工具 pill，不将查询结果当用户回答；工具完成不等于最终 Goal 完成 |
| wait user | 任务投影有 waiting_input/waiting_approval，与聊天 turn 终态分开 | 不能由通用 loading 推断需要批准；本批未接原生确认 UI |
| reconnecting / unknown | events cursor 支持读取原 turn；原生忽略已收序号，gap/EOF 不猜完成；failed 的 reconciliation 决定 unknown | 按同一请求核对，不自动重发副作用。连接状态仍须独立展示，恢复屏障属于后端权限限制，不是动画阶段 |
| cancelling / cancelled | 本地 notSent/cancelledBeforeSend 与 stopObserving 可区分；服务端另有 pause/revoke | 停止观察不等于云端取消。未来停止按钮需对应真实控制回执，本规格不扩充当前取消接口 |
| complete | `turn_completed` 携带 final_text_hash；原生校验最终 message ID、全文hash和未结工具 | 仅完成回复；task succeeded、Outcome及现实 Goal 完成是不同权威。EOF/动效计时器不驱动成功 |
