## 1. 设计 Goal 与对标依据

终版整合见[FINAL-1产品设计](../product/catpaw-final-product-spec.md)与[流中决定／审批／成果／跟进交互预览](prototypes/catpaw-final/index.html)。保留本UX-1的布局与原生验收身份；下面补充产品行为，网页只是人工提案，不能关闭AF-U。

**AF-GD：用户在 iPhone 上能顺手发起、理解、引导、批准和查收 Agent 工作；导航、输入、长文阅读、任务/成果和全状态视觉达到本文要求，AF-U01–12 在同版原生 App 上全部通过。** AF-GD 是 AF-G5 总 Goal 的必需部分。静态设计、网页预览和 Simulator 只能支持设计评审，不能关闭原生真机体验验收。

本次从[已找回的截图与会话观察](ios-codex-reference-review-2026-10-13.md)继续，不要求再次解锁或重录。记录中 ChatGPT 的对话输入简洁，侧栏区分“你的 dot / 定时任务 / 空间 / Codex”，名称菜单承载电脑和暂停等次级控制。这里仅继承已观察的结构，不声称已测量 Codex 每个界面的像素。

官方 mobile 文档把发起、跟进、批准和审阅放在手机工作循环；据此将 cat 的任务状态、待决事项和成果作为可直接操作的信息，而不是调试面板。[Codex on mobile](https://learn.chatgpt.com/docs/mobile)。官方 iOS 变更记录介绍优先呈现运行中、未读和等待用户的任务，以及可编辑队列；这些是行为参照，不代表 cat 已有同等后台队列能力。[2026-09-01 changelog](https://learn.chatgpt.com/docs/changelog)。

桌面 Codex 的信息组织用来支撑目标/计划、线程、动作审阅和产物回流；iPhone 使用单列和原生详情，不直接缩小桌面多栏。对标的工作引导与审阅模式参见 [官方 mobile field guide](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)。以下具体间距、色彩和布局是 cat 的设计决定，不标成 Codex 官方参数。

## 2. 产品信息架构

```text
默认入口：当前对话 / 新对话
  ├─ 侧栏：搜索 / 新对话、需要你 / 有新成果（有内容才出现）、最近对话
  │         活动、资料与管理（展开工作 / 成果 / 跟进 / 记忆）、设置
  ├─ 原消息：计划 / 等待确认 / 成果的轻量入口
  ├─ 任务详情：目标与当前状态 → 待决事项 → 计划进展 → 成果 → 工作约定
  └─ 成果详情：内容与来源 → 版本 → 继续修改
```

主对话不叠加永久底部 TabBar。常用路径从对话一次点按进入任务、审批或成果；全局入口放侧栏，最近成果也能从活动找回。桌面项目/主机结构只在已实现且用户需要时显示，不强制每次聊天先选仓库或执行环境。

优先事项按等待用户、未读结果、正在执行组织，已读历史按近期分组；同一任务只计一次，同对象多入口共用状态。收件箱标记已读后保留成果；会话归档与删除分别处理，界面不能借“归档”清除数据。

侧栏首层用“活动”统一等待/未读/运行；“资料与管理”为可展开组，工作、成果、跟进、记忆仍各有直接入口。不要同时显示同计数的“任务/活动/等待我”三排大卡。设置在底部，连接详情收在设置中。多项待决按执行依赖与期限排序，摘要可见剩余数量；只收紧层级，不删除领域入口。

## 3. 主对话布局

自上而下：系统状态与安全区、紧凑导航栏、单列滚动对话、按需队列摘要、底部输入器和系统安全区。正文是屏幕主要面积。

导航栏左侧44pt菜单，中间会话/助理名称与可选次级菜单，右侧44pt新会话动作。普通导航内容高度以系统导航栏为准；名称超长截断，完整名称在详情可读。模型供应商、连接诊断、预算和内部状态不常驻主标题或底部。

用户消息采用靠右轻色气泡（R5浅色轻蓝、深色深蓝），普通字号最大宽度为内容区86%；助理回复直接排版在内容区，不用大外框包住每条回复。角色不重复画大头像。正文间距稳定，时间/状态按需出现，工具步骤默认折叠成一行，展开才看细节。

任务卡首层只保留标题、真实状态/当前步骤和一个最相关动作；成果卡显示标题、类型/版本及“查看成果”。内部 operation/hash/epoch 等只在“详细信息”中可查；技术字段不挤占常规阅读。

新会话为空时使用简短起始句“今天想交给我什么？”和至多两条可点示例，点示例填入草稿，不自动发出。没有工具支持的示例不展示。新会话切换保留旧草稿和待发项，不能误把上一会话的回复投射到新会话。

首次打开不强制功能巡游；已有Auth/配置为发送必需时就地说明并保留草稿，不假设可跳过云端身份。模型处理许可在首次相关发送出现；相册、日历、通知权限只在相应动作需要时申请。默认输出先采用简短结论＋适用的表与来源；用户可改，格式偏好不成为开工阻断。只有影响正确性、范围或写入后果的缺失字段才问一个具体问题。

主流里每项工作只有一个当前摘要：工作名、实际步骤/等待原因、一个最相关动作。常规计划的完整步骤进详情；当前待决用卡，回答后压缩为决定摘要；完成时显示成果标题、摘要和打开入口。历史决定仍可展开查阅。不能每个事件都插入新卡，或同屏把choice、完整plan与普通工具进度都画成等权重面板。卡必须使用当前事项的目标，禁止日程状态配研究计划。

## 4. 输入器、附件与队列

输入器为一个圆角容器：文字输入、左侧附件入口、右侧主动作；单行起，随内容增高至默认字号最多五行，再内部滚动。大字号按屏幕可用高度约束，不固定五行像素。长文可进入原生全屏编辑，返回保留草稿与光标。

Send始终是显式动作；中文 marked text 不触发发送。发送后本地消息立即出现。运行中右侧显示“排入队列”，停止当前生成单独给出明确控制；不让同一无标签图标在发送/停止/取消云任务之间隐式变义。

队列默认只用一行“2条待发 · 已暂停/等待当前回复”，点开 sheet 查看、编辑、移除和继续。未发送文本不再重复显示成正式对话消息。首版是本地待发队列，App关闭不保证新增消息送达；只有服务端持久受理后才可标“已提交”。不从 Codex 的后台队列功能推定本产品已有该行为。

附件从一个入口进入可用来源。首版只显示真正接通的图片来源；预览以80–96pt的有界缩略图位于同一输入容器上方，可点开完整比例、移除、替换。默认保留完整图片，特殊比例不被裁切成难辨长窄条。许可详情按需要打开，预览控件与授权不散成多块大面板。

键盘升起时输入区跟随系统安全区，最新输入/主动作可见；阅读区域缩小且保持滚动锚点。键盘收起不清除文字。输入图片或切页失败都保留可恢复的草稿。

## 5. 流式阅读与直接引导

用户在底部阅读时，新增回复跟随底部；用户向上读时保留位置，出现轻量“回到最新”按钮。增量不能令文字反复重排闪烁、标题逐字跳动或回复整体被替换回较短版本。

段落、标题、列表、链接、代码和表格使用一致阅读样式。表格/长代码只在自身容器横向滚动，不把整个对话扩成横向画布；正文可选择和复制。来源链接可查看，外部链接失败仍能返回原位置。

继续输入默认进入明确队列。用户改变任务目标可从计划卡“修改要求”进入同任务的新 revision；没有独立可验收的中途 steer 通道时不声称新文字即时改变正在执行的步骤。模型流结束与持续任务结束分别呈现。

修改模式用composer上方关联条显示工作名和退出操作，普通聊天/修改各有草稿。退出保留修改草稿、恢复聊天草稿，不暗中提交或结束工作。普通Send保持含义稳定；修改模式的发送辅助标签说明“提交对此工作的修改”。提交受理与实际应用分别反馈，未知只核对。停止生成在流的工作状态旁保持可发现，不挤占Send或把停止文字流等同取消云端工作。

FINAL-1细化：完整schema与权威对象就绪后，choice/form/approval即可回答，不等待同turn所有正文结束。渲染阶段与任务阶段分开，未完整参数只读；同cardID增量更新不重建整条消息，不丢字段焦点、输入或阅读锚点。“修改要求”在输入器显示关联工作，服务端受理新revision后在安全点应用；参数变化使旧审批失效，已发生效果仍可查。对应FQ-01/02、AF-U06–08。

[CGUI-1](conversation-generative-ui-spec.md)补充正文／成果中的原生table、bar/line与确定试算器：控件和字段局部更新，同数据／来源／版本；标题、关键结果、参数、假设、重置与显式跟进按同列排布。排序／调参本地完成，点“用此方案继续”才向原会话／工作受理后续turn或安全点修改；不宣称同SSE双向中断。图有可访问数据表替代入口，只有表自身横滚。原12项UX保留，[CG-A01–10](../acceptance/conversation-generative-ui-acceptance.md)作为终版FQ细分覆盖新呈现与恢复，不用网页代替原生验收。

## 6. 侧栏、详情与审批

侧栏为左侧抽屉，默认宽度 `min(320pt, 屏宽×0.86)`，右侧保留可点击遮罩；支持菜单打开、遮罩/向左滑关闭。边缘侧滑须避免和任务详情的系统返回手势冲突。打开/关闭不抹草稿，切会话记住各自位置。

顶部搜索和新对话，优先事项与历史是主内容；活动为稳定紧凑行，工作/成果/跟进/记忆归可展开的资料与管理；账户和设置在底部。新入口不一律配大卡片。搜索状态包含空、加载、命中和无结果；没有结果时能清除搜索返回。

任务、成果和记忆使用 NavigationStack 详情；简单选择、队列、许可预览用 sheet。详情有系统返回，sheet有显式关闭及合理拖拽关闭；审批关掉之后原消息/任务仍有持久入口。sheet的“关闭”不等于拒绝/批准。

审批顶部用一句人话说明“需要你确认什么”，随后给处理方或动作、目标、关键参数和影响范围；主按钮明确“允许此对话”或“确认创建日程”，次按钮“暂不允许/拒绝”。审批正文可滚动，主要决定动作在安全区可达；大字号时动作垂直排列。触碰后先显示处理中，服务确认后才成功。

任务暂停、停止观察、本地队列暂停与取消云端工作用不同名称；取消已运行任务说明将停止后续步骤。结果未知展示“核对执行结果”，不提供会造成双写的重发按钮。

决定来自持久对象。手机离线仍保存待答／待批入口；拒绝不能被换toolCall绕过。展示动作、目标、参数、范围与期限，不依风险标签自动批准或机械要求双弹窗。receipt已存而续聊失败时只恢复交付；sheet关闭、已读和决定各自记录。对应FQ-02。

审批需要用户时显示可找回卡，不自动弹出sheet打断正在阅读的正文；只有用户打开卡或进入明确确认流程才展示预览。完整参数保留，主动作具体命名，拒绝与稍后关闭分别解释。轻审批sheet将可滚动正文与底部决定区分开；内容太长或需多字段编辑时进原生详情，不缩字号。收到真实回执才显示一次完成反馈，等待/unknown不播放成功反馈。

## 7. 成果、记忆与持续跟进

成果详情先内容后元数据；标题/版本/来源紧凑呈现，底部一个“继续修改”动作返回原会话携带同成果引用。大量来源可折叠，版本/hash在详情可查。比较结果在正文表格或比较卡中完整可读。

交付时用一句话说明完成了什么，首屏给实际关键结论和可读内容；“部分完成”说明缺项与下一步。复制正文与系统分享作为成果操作可发现；已经实现的文件格式才显示保存/导出，首轮文本成果可复制/分享原文与来源，不伪称已有PDF/Office导出。分享使用当前可读版本，不执行写工具，不将临时失效URL作为唯一成果。固定底部动作与工具栏分工，不能四个主按钮一起盖住正文。

历史成果卡保存稳定对象引用，重开读取对应版本和当前访问链接，临时签名 URL 不作为永久消息内容。加载失败显示“重新读取成果”；动作已成功但页面刷新失败时同时保留成功状态和重读入口，不能把按钮改为再次执行。切换会话/成果后的迟到响应不覆盖新页面；继续修改携带预期版本，冲突时保留用户草稿并展示版本变化，不静默覆盖。

记忆页采用原生列表：内容、来源/范围、确认状态；详情支持更正和删除。更正后展示新版本；删除有明确反馈，并保持返回位置。不能用一个总开关代替逐条记忆控制。

跟进页展示约定、状态、下次时间、最近变化和暂停/结束。没有变化不用制造新对话消息；有变化的一条收件箱记录点开同成果。空页说明可从对话创建，示例仍只填草稿。

创建/编辑的首层只显示来源/条件、频率/时区、停止和静默；预算、重试等放可展开细节，提交摘要仍能核对完整约定。更改静默开关不重建并清空尚未保存的字段；离开编辑不伪装已保存。回到App只按真实变化显示一条紧凑摘要，并回同事项/位置；没有变化无需欢迎卡或新消息。

## 8. 视觉系统

沿用 [现有 semantic tokens](design-tokens.json) 和A1正式图标；UI主体使用中性灰阶、黑白主动作、蓝色文字操作和独立状态色。品牌图标保留在应用图标/必要身份位置，主对话不增加大吉祥物或渐变背景。

| 项 | cat UX-1决定 |
|---|---|
| 页面 | 使用现有background/panel语义；主阅读为不透明surface，清楚区分内容和控件 |
| 颜色 | 文字ink/secondary；输入input；主按钮ink/onInk；状态兼具图标/文字，不只靠颜色 |
| 字体 | 系统动态字体；body默认17pt、导航headline、次级subheadline/caption；长中文行距约1.45–1.55 |
| 间距 | 主内容左右20pt；卡片内16pt；同组8/12pt、内容块24/28pt；大字号可增高自然换行 |
| 圆角 | composer24pt、卡20pt、常规控件14pt；层次靠留白/浅分隔，不堆重阴影 |
| 点击 | 主要操作至少44×44pt，点击区可大于图形；图标用现有SF Symbols语义 |
| 运动 | 导航/sheet/键盘使用系统过渡；按压120ms，有限状态180/240ms、抽屉280ms；细则见R2，Reduce Motion取消位移/缩放 |
| 深色 | 成对semantic色，禁止简单颜色反转；图片本色保留，状态/按钮在深色仍清楚 |

主阅读正文与关键次级文字使用4.5:1对比目标；非文字控件边界/状态目标3:1。实际组合需测量，token计算不代替渲染后的可读性。Dynamic Type、可感知状态和触控尺寸依据 [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility)，本文采用44pt作为产品底线。

视觉优先级是正文/成果内容→当前需要用户的决定→工作摘要→工具/元数据。每区块一个最相关主动作，不限制必要的停止/拒绝/修改入口。常规摘要用留白与轻分隔，决定和成果才按需用容器；品牌不靠全屏强色表达。

Liquid Glass优先由系统导航/控件采用，长文、表格、成果正文保持稳定不透明阅读层；低版本用已有原生样式，不做玻璃模拟或更换A1。系统设置的增加对比/降低透明度应生效，基于实际部署目标实现。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

触觉只在适用的明确决定或真实完成反馈中克制使用，不按每个token/步骤触发；成功反馈同时用文字和符号，无声/关闭触觉仍能理解。VoiceOver不逐token打断朗读，状态在有意义阶段变化时通知，焦点留在用户正在编辑的字段。按压仍沿现有120ms；R2只为有限状态变化补180/240/280ms设计值，系统转场不覆盖，尊重Reduce Motion；不添加装饰性加载循环。

R2将正文、工作摘要、当前决定、成果阅读器和输入器落实为组件层级；字体/边界/间距见[实施附录](taste-visual-motion-r2.md)和[机器参数](taste-visual-motion-r2.json)。沿用冻结颜色与A1，只增加必要控制边界色。决定/成果的局部过渡保持对象ID、输入焦点和阅读锚点；真实回执才给一次成功反馈，历史重开不重播。细则是本UX-1附录，不新增产品或执行权威。

## 9. 完整状态矩阵

每个主页面都有正常、空、加载、失败和适用的离线状态；动作页另有未批准、处理中、批准/拒绝、过期和unknown。状态变化保持同对象和同位置，不能仅有spinner或“待验证”。

| 场景 | 首层显示 | 用户下一步 |
|---|---|---|
| 无配置 | “尚未配置模型” | 去设置 |
| 等许可 | “需要确认处理方式” | 打开持久许可详情 |
| 排队 | “已保存在本机 · 待发送” | 查看/暂停/编辑队列 |
| 已受理/运行 | 当前实际步骤，必要时经过时间 | 查看计划/停止适用操作 |
| 等条件/设备 | 一个具体问题或“打开App完成日程操作” | 回答/打开设备动作 |
| 失败 | 具体可理解原因 | 修改输入/核对适用重试 |
| 结果未知 | “执行结果未确认” | 只读核对原操作 |
| 成功 | 成果标题和真实完成状态 | 查看/继续修改 |

连接状态只在设置详细显示；“曾完成真实回复”须带时间和处理方，不用绿灯暗示所有工具/图片/后台能力都可用。

2026-10-13 [四仓源码核读](../research/copilotkit-four-repo-decision-update-2026-10-13.md)细化卡片状态：生成中只显示标题/摘要/骨架；参数或对象未就绪时不出现可提交动作。完整受控 schema 与当前对象就绪后显示操作，提交期间阻止重复点击；超时无回执进入核对状态。待审批/待回答入口在工具活动折叠区外保持可见；手机离线时服务端保存待决事项，重开恢复同一记录。展示卡已保存不等于用户已看见；未知卡可读降级并进入原事项。六类卡使用同一字体、间距和44pt操作规则，不嵌入模型生成脚本。这是 UX-1 状态细化，不新增卡种或改变现有 wire 合同。

## 10. 设计交付与验收顺序

R2可点按视觉/动效提案已覆盖主对话/输入、侧栏、任务/审批、成果、试算、跟进与异常状态；全部为人工状态，不代表原生交付。先固定主对话/输入、侧栏、任务/审批、成果四组界面与关键状态，给出可点按布局提案；设计评审反馈成为版本化决定，再实施 SwiftUI。记忆/跟进复用同一视觉规则。功能修复可以继续，但新页面不边写业务边随意拼组件。

用户可审阅：信息架构、布局预览、交互转换和UX用例；原生交付另给375/390/430pt、小屏+键盘、浅深色和最大辅助字号矩阵，以及同版真实流程记录。发现设计差异时回到同一个规格修订，不把体验改造留在全部功能完成之后。

本预览使用合成数据与内存交互，未连接模型/服务/EventKit；不是原生App或通过证据。HTML中的轮廓图标用于设计示意，原生实现使用已登记SF Symbols。原生字体/键盘/手势/安全区/屏幕帧均需独立验收。
