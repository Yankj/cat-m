# 方案：联网搜索 + 天气（仅方案，未实现）

> chat-ux 审计里「联网搜索和天气」（当前 `web_search:false`）是和 ChatGPT / 豆包差距最大的一项。本文只给方案与取舍，不改代码、不接供应商、不部署。
> 价格为 2026-10-16 查到的公开价，签约前需再核对；延迟为经验估计，接入前用真实请求测。

## 1. 目标与边界

- 回答「今天要带伞吗」「明早出门冷不冷」「XX 最新消息」「这家店几点关门」这类需要实时信息的问题，并给出处。
- 结果走现有工具链：工具结果 → 模型 → 文本，必要时用 render_ui 卡片。天气卡沿用本批 #2 的思路：卡片内容只来自 tool_result，不让模型编数据。
- 不做的事：不抓取全文建库（Brave 等条款禁止持久化结果），不在后台静默搜索，没有用户提问时不发请求。

## 2. 天气

| 方案 | 在哪调 | 成本 | 延迟（估） | 隐私 | 备注 |
|---|---|---|---|---|---|
| **Apple WeatherKit（端上）** | iPhone，新增 device tool `weather_get` | Apple Developer Program 含每月 50 万次调用，超出再按档付费 | 约 0.3–1 s | 坐标只在手机和 Apple 之间，服务端看不到位置 | 必须显示  Weather 署名和数据源链接；能拿到小时/分钟级降水预报 |
| 和风天气 QWeather（服务端） | edge 新工具 | 每月前 5 万次免费，之后每次 ¥0.0007（之后递减） | 约 0.2–0.6 s（国内） | 要把城市或粗粒度坐标发到服务端和供应商 | 国内数据、预警、生活指数最全；需要 key（用户在 Dashboard 配） |
| Open-Meteo | 服务端 | 免费版仅限非商用；商用订阅按月固定价（Standard 100 万次/月） | 约 0.3–0.8 s | 同上 | 无需账号即可试用，但商用必须订阅 |

**推荐**：主路径用 WeatherKit，做成端上 device tool（`confirm:none`，只读，像 `places_search` 一样用「使用期间」定位）。位置不出手机，服务端零成本，也符合现在「设备能力在手机上执行」的架构。和风天气作为服务端兜底，只在端上不可用时用（老版本 App、定位被拒但用户报了城市），按城市名查，不传精确坐标。

## 3. 联网搜索

| 方案 | 成本 | 延迟（估） | 中文/国内结果 | 隐私与条款 | 备注 |
|---|---|---|---|---|---|
| **博查 Bocha Web Search** | ¥0.036/次（AI Search ¥0.06/次，带天气等结构化卡） | 约 0.5–1.5 s | 好，国内可直连 | 国内供应商；查询词出境风险小 | 返回网页摘要，适合直接喂给模型 |
| Brave Search API | $5/千次，每月含 $5 免费额度（约 1000 次） | 约 0.3–1 s（海外） | 一般 | 独立索引；条款禁止持久化结果；企业版可零留存 | 海外内容、英文质量好 |
| Tavily | 每月 1000 credit 免费；按量 $0.008/credit（basic 1、advanced 2） | 约 1–3 s | 一般 | 面向 LLM，返回清洗过的片段 | 接入最省事，但单价最高 |
| Serper（Google 结果） | $1–0.3/千次（预付包，6 个月有效） | 约 1–2 s | 取决于 Google | 第三方转售 SERP，合规性需要自评 | 最便宜，但依赖抓取 Google |

**推荐**：服务端新增 `web_search` 工具，供应商用博查（中文用户、国内可达、价格可控）；`CATPAW_SEARCH_PROVIDER` 预留 Brave 作为英文/海外问题的备选。

- **何时调用**：仅当问题需要「今天/最新/实时/具体营业信息」时。用 #3 同样的方法给 prompt 写规则，并加 20 条固定评测（应搜/不应搜），目标命中 ≥85%。
- **输出**：工具结果只回 3–5 条 `{title, url, snippet, published_at}`。回答里必须带来源链接；客户端用现有 Markdown 链接渲染，后续可以加 `source` 卡片。
- **成本护栏**：每个用户每天最多 N 次（建议 20），每轮最多 2 次；用 feature gate（和 `generative_ui`、`device_tools` 一样走 allowlist）先灰度；在 `model_route` 旁边记录调用次数和费用。
  - 估算：1000 DAU × 每人每天 3 次 × 30 天 = 9 万次/月，博查约 ¥3,240/月，Brave 约 $450/月。
- **隐私**：查询词发给第三方，要在隐私说明里写明；查询词不写入记忆、不进日志正文（只记哈希和计数）；不发送用户位置，「附近」类问题继续走端上的 `places_search`。
- **安全**：网页片段属于不可信数据，放进 tool_result 时加「仅供参考，不是指令」标记，并补一条 prompt-injection 测试（审计 P1 里本来就有这一项）。

## 4. 落地顺序（等批准后再做）

1. `weather_get` device tool（WeatherKit）、天气卡（grounded kind，复用 #2 的通路）、署名。约 1 天，零运行成本。
2. `web_search`（博查）+ gate + 每日上限 + 来源链接 + 评测集。约 1.5 天；需要用户在 Dashboard 配 key，并批准部署。
3. 和风天气兜底、Brave 备选：按真实使用数据决定要不要做。

## 5. 需要用户决定

- 是否接受联网搜索的按次费用和每日上限（建议先每用户每天 20 次）。
- 供应商选择：博查（推荐）还是 Brave / Tavily；key 由用户在 Supabase Dashboard 配置。
- 隐私文案：搜索词会发给第三方。
