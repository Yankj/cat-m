# v0.2 text loop (backend) — evidence

Branch `feat/family-v02-text-loop` (stacked on `feat/family-backend-m1m2`). Not deployed. No production DB touched.

## What exists
- Migration `20261023200000_family_v1_core.sql` (file only, not applied to prod): schema `family` — households (one per adult), members (children), plans, items, proposals, observations, reminders, receipts, outbox, command registry; single-adult RLS (select-only for `authenticated`, owner-scoped; writes only via `family.apply_command`, executable by `service_role` only).
- `family.apply_command(actor, cmd, hash)`: idempotency on `(actor, household, command_id)`; domain write + revision + receipt + outbox in one transaction; deterministic rejections are committed `rejected` receipts with domain rolled back (sub-transaction).
- Commands: household.ensure/update, child.upsert/delete, plan.upsert/pause, item.propose/confirm/correct/cancel/reschedule, observation.record/correct/delete.
- Read APIs: `GET /bootstrap`, `GET /commands/{id}`, `GET /households/{id}/projection?local_date=` (today.schedule / pending_confirmations / reminders, conversation, home — one SQL snapshot), `GET /households/{id}/changes?after=`.
- `POST /households/{id}/captures` (kind `text` / `voice_transcript`): deterministic zh-CN extractor -> `item.propose` cards; command ids derived from `capture_id` so retries do not duplicate. Unknown date/time/child stay null and are listed in `missing`.
- Wired into `catpaw-api` behind `CATPAW_FAMILY_ENABLED` (default **off**).
