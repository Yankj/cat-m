# v0.4 memory + reminders + M3 gate (backend) — evidence

Branch `feat/family-v04-memory-reminders` (stacked on `feat/family-v03-photo-home`). Not deployed. No production DB touched.

## What exists
- Migrations (files only): `20261023300000_family_v1_memory_reminders.sql`, `20261023300100_family_v1_memory_fences.sql`.
- Household memory facts: `memory.upsert/correct/delete` (CAS; tombstone scrubs text; replay of the delete returns the same receipt; upsert by a deleted id → `previously_deleted`), `memory.pause` (recall empty, writes refused), no-relearn generation fence, `child.delete` cascades to that member's facts, `household.delete`.
- Recall: SQL filter (owner, household, status, validity window, subject, visibility) + lexical char-bigram ranking, top 6. No embeddings (no provider; compute budget zero).
- Reminders: `reminder.schedule/cancel/pause`; only for confirmed items; kinds limited to 3; `why_now` ≤ 80; quiet 21:00–08:00 household time; ≤ 2 scheduled per local day; reschedule must include `replace_reminder` when reminders exist; item cancel cancels reminders.
- Dispatcher: `claim_due_reminders` (30 s lease, skips paused households / non-scheduled items), `fire_reminder` (atomic re-check, writes outbox `reminder.due` once), `release_reminder`; JS `runReminderTick`.

## M3 memory gate (frozen corpus `memory-cases-v1.json`, 100 cases)
Run through the HTTP service on real PG; harness keeps gold/expectation fields; seed order is the corpus' SHA-256 order. Result file: `m3-gate-run-2026-10-23.json`.
- **macro recall@6 = 0.98** (threshold 0.90), micro 51/52 = 0.981, identical on repeated runs after the deterministic tie-break fix. Query-blind control in the corpus doc: 0.72.
- **Forbidden refs in top 6: 0 of 100 cases.**
- 29 of 47 step operation kinds are executed via real commands or documented no-ops; 18 kinds are unsupported; 23 cases (all non-eligible negatives) contain at least one unsupported operation (`extract_voice_fields`, `extract_image_fields`, `freeze_recall_snapshot`, `resolve_before_output`, `revoke_membership`, `switch_account`, `undo_forget`, …). For those, only "no forbidden ref returned" is checked.
- **Not checked** (NOT_RUN): clarification fields, dispositions, answer assertions/used refs (no model in the loop), per-step expected pre/post state, read/write counts. Per the corpus rules the full M3 suite is therefore **not PASS**; only the retrieval sub-gate and forbidden-ref check passed.
- Adapter mappings that are interpretations: `retract_source` / `revoke_source_access` → delete derived facts; `disputed` seeds stored as active facts; `confirm_this_time_only`, `import_older_notice`, `expire_raw_media`, `edit_extracted_field` → no memory write.
- History: first run 0.72 with 9 forbidden-ref cases; fixes added restricted→private visibility, no-relearn fence, household delete, member-delete cascade, client use_memory/ephemeral flags, revision alignment.
