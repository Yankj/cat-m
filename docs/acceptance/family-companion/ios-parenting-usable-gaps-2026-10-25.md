## 2. 本批实现：本机提醒（M2c 的最小可用版）

- 仅提醒**已确认**（`planned`）且未来的安排。待确认、已取消、已完成的永远不提醒。
- 默认**关闭**；系统通知权限只在家长点“开启提醒”时才请求，不在启动或后台请求。
- 提醒时间：提前 15/30 分钟、1 小时或前一晚 20:00，可选。落在 21:00–08:00 的提醒挪到前一晚 20:30，并在通知文字里说明“为避开夜间安静时段，已提前到前一晚提醒”。
- 每个本地日最多 2 条；超出的不静默丢弃，在对应安排上显示“未提醒：当天已有 2 条提醒”。已经响过的提醒占用当天额度。
- 已过提醒时间的不会补一个立刻响的通知，如实显示“未提醒：提醒时间已过”。
- 只有从系统读回（pending 请求存在且签名一致）才显示“将在 X 提醒”。系统拒绝或读回缺失时显示“提醒状态未确认”，设置里提示重新打开。
- 提醒时间过后，用本机记忆把它标为“提醒时间已到”，不会误报成“漏了”。这只说明本机已排过且时间已到，不证明系统一定展示过（专注模式等可能抑制）。
- 锁屏内容可选隐藏孩子名与事项名。
- 账号：提醒标识含账号 id；展示/点击前核对当前登录账号；退出登录时清掉全部育儿提醒；系统写入前后都核对账号仍有效，失效则撤回刚写入的提醒。
- 设置在每个账号自己的 `UserDefaults` 键里，不进加密账本，旧账本无需迁移。
- 提醒只在本机发送，不经服务器，不用 APNs，不写系统日历。

不在本批：通知按钮（完成/推迟）、通知点击直达某条安排（点击只回到 App 的“今天”）、APNs 远程提醒、家庭云同步。

## 3. 验证状态（区分层次）

| 层 | 结果 |
|---|---|
| 规划与调度逻辑 | 在 Linux 用 Swift 6.0.3 的独立 SwiftPM 壳编译并跑 19 个 XCTest 全过：规划器 9（仅确认项、静音挪动、每日 2 条、已响不算漏、48 条上限、账号归属等）、调度器 10（读回才算数、幂等、改期/取消/删除跟随、拒绝与未授权不弹窗、隐藏内容、他账号与外部通知不被触碰、账号中途失效撤回、记忆）。壳里 `CryptoKit` 的 SHA256 与 `AppLanguage` 是替身，只用于编译运行这批纯逻辑，不是生产实现的证据 |
| iOS 编译、SwiftUI、系统通知适配、模型层 2 个集成测试 | 依赖 iOS SDK，本机 Linux 无法编译，**以本 PR 的 CI（macOS 构建 + 模拟器）为准**；结果见 PR 页面，不在本文预写 |
| 模拟器/真机截图、真实系统通知送达 | **未做**：指定的两台 Mac 当时离线；没有使用其他电脑。真实 iOS 是否按时展示通知、专注模式/通知关闭的表现，均未验证 |
| 真实后端、真实家庭 | 本批不涉及后端；没有真实家庭验收，不用 mock 冒充 |

现有 8 条 UI 旅程使用的合成夹具不带提醒权限（调度器为空），界面文案与现有断言（含 `Local arrangements send no reminders`）保持不变；提醒相关界面因此没有 UI 自动化覆盖。

## 4. 需要用户做的事

1. 审 PR；在真机或自己的模拟器上开启提醒，建一条 1 小时后的安排并确认，核对到点通知、锁屏隐藏、拒绝权限后的提示。
2. 决定每天最多 2 条提醒是否够用（对应产品定位里的“每天最多 1–2 条”），以及超出时是否改为合并成一条摘要。
3. 批准后再推进：账号删除端点、一句话整理端点的线上核对/部署、图片与语音抽取（均涉及后端或生产）。
