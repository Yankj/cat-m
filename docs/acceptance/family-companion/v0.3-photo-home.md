# v0.3 photo notice + 我们家 (backend) — evidence

Branch `feat/family-v03-photo-home` (stacked on `feat/family-v02-text-loop`). Not deployed. No production DB touched. No new migration.

## What exists
- `POST /households/{id}/captures` with `kind:"image"`, `image:{mime,data_base64}`: PNG/JPEG bytes validated by the existing `validateImageBytes` (≤5 MiB, ≤2048 px side); body limit for captures raised to fit one image (other routes stay 32 KiB). Bytes go to the injected image extractor and are never stored; items keep `source_kind=notification_extract`, `source_ref=capture:<id>:<n>`.
- An image extractor may return structured candidates or the notice text; text goes through the same zh-CN extractor (dates first by explicit 月/日, then weekday; `X前/截止` marked as deadline → notes `截止日期`; `…集合` → place; `带…` → bring list).
- Without an image extractor configured the route answers `422 capability_unavailable` (no fake success).
- 我们家: `GET /households/{id}/home` (household, children, plans, observations; memories added in v0.4). Edit/delete via existing commands: `household.update`, `child.upsert` (CAS, fields nullable), `child.delete` (tombstone, name scrubbed), `observation.record/correct/delete` (tombstone, text scrubbed).
