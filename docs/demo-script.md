## 2. 逐场脚本

### S1 开场
> 这是 Catpaw-m，你的个人 AI 助手，一款 iPhone 原生 App：把交代的事，变成可用成果。今天重点看它的主动能力——什么时候该开口，什么时候该闭嘴。

### S3 产品思考
> 四条规矩：宁可沉默，不可说错；时机在手机上抓，云端兜底；每一次介入都能确认、能解释、能撤销；记忆是一等公民，用到的偏好在设置里看得见、删得掉。

### S4 一次介入怎么决定（README 场景 A）
幻灯片 5 旁白：信号 → 去重 → 记忆召回 → 模型结构化决策（不可用走规则兜底）→ 置信度不足降级 → 静默时段与每日上限 → 只写一条带解释的事件。

现场：
1. 「设置 › 调试 › 主动信号模拟」，镜头扫过「构建」区 git SHA。
2. 「会前提前量（记忆）」调到「提前 15 分钟」，点「写入记忆并生效」。
3. 点「打开 设置 › 记忆」，停在新记忆条目，返回。
4. 可选：选「模拟起点」或「请求定位权限（When-In-Use）」。
5. 「一键注入」点「注入 N 分钟后·望京 SOHO 的会」。
6. 回到对话，出现「小猫主动提醒」卡片，点「为什么找你」。
7. 停 3 秒展示日历信号、提前量、路途、出发时间；如有「参考了 N 条记忆」，点「打开记忆页」。

> 出发时间 = 开会时间 − 提前量 − 路途。没有定位时它会直说「未用到 ETA」，不会拿假起点来算。（无定位时显示「未用到 ETA」是预期行为。）

### S5 四级主动
> 静默、应用内卡片、普通推送、紧急打断。只有会造成损失（迟到、误机、冲突）才推送或打断；专注模式下没把握的打断降为推送；推得太多降为卡片；静默时段的推送推迟合并。

现场：镜头对准卡片上的「创建提醒」「告诉参会人」「稍后」「不用了」，只展示不点。

### S6 撤销（README 场景 B）
1. 卡片上点「创建提醒」（首次会弹提醒事项权限，同意）。
2. 可选：切到系统「提醒事项」展示新提醒。
3. 打开「为什么找你」，点「撤销」。
4. 可选：回「提醒事项」确认已删除。

> 提醒写进了系统提醒事项；一键撤销，提醒删掉，出发倒计时一起结束。短信这类发出去收不回的，不会假装撤销，而是如实保留「已发送」记录。

注意：模拟器无法发短信，**不要点「告诉参会人」演示发送成功**。

### S7 账号停放与恢复（README 场景 C）
1. 账号 A 下确认有一张主动卡片（或先点「稍后」制造待同步状态）。
2. 从账号入口点「退出此账号」，确认「退出此账号？」。入口位置 TODO：以 #90 构建为准。
3. 登录账号 B：看不到 A 的卡片。
4. 退出 B，重新登录 A：卡片自动回来，无弹窗、无提示。

> 切换或退出时，账号的卡片、提醒上下文、未同步操作都停放在它自己名下，不清除也不弹窗。B 看不到、也不会以 B 的身份发出 A 的数据。系统提醒事项里已建好的提醒不会被自作主张删改。

注意：外部提醒的保留 / 删除决策界面属于 #89，尚未完成，不演示、不说已有。

### S8 离线同步（可选）
断网 → 卡片上点「稍后」→ 恢复网络回前台，状态保持一致。
> 离线的「稍后」「不用了」「撤销」先存本地持久队列并按账号打标，联网后按原账号补发；已判定失败的不偷偷重试，留待确认。

需要已部署的 #90 服务端；看不出同步效果就只放幻灯片。

### S9 多设备推送（可选）
> 每次推送绑定一个代次，最多发一次；每台设备发送前再查一遍，用户已在一台设备点「不用了」，其余设备停发。结果不确定时不重发——宁可漏一次，也不重复打扰。

仅在两台真机、APNs 与新服务端都就绪时拍摄。

### S11 架构
> 手机上是 SwiftUI 原生 App，负责抓时机、展示卡片、调用提醒事项和地图。云端两个 Supabase Edge 函数：catpaw-api 负责对话、模型路由和记忆；catpaw-proactive（#90）负责主动决策、任务和推送。数据在 Postgres，pg_cron 每分钟调度，推送经 APNs 回到手机。

## 3. 剪辑

幻灯片中的「录屏」虚线框是贴片位：5 →「为什么找你」面板；6 → 建议卡片；7 → 退出再登录；8 → 创建提醒 → 撤销；9 → 双设备推送。旁白可直接用作字幕。
