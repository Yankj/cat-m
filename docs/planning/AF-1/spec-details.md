# AF-1 详细功能规格

版本：AF-1-G3-UX1，2026-10-13。细化 [主 spec](../../product/agent-foundation-spec.md) 的 AF-R01–12；历史 v1/v2 HTTP 合同、上游受控来源和已交付 v1 保持身份。本文定义预期行为，不宣称实现已完成；当前进展仅见 [master-plan](../../status/master-plan.md)。

## 1. 用户问题与解决方案

用户需要从自然对话把工作交给 Agent，并在工作跨时间、跨 App 生命周期时知道它在做什么、需要自己决定什么、结果在哪里。此前许可会消失、队列占据阅读空间、状态缺少真实证据，且源码/安装/部署版本混杂，导致用户无法走到模型验证，也无法判断进度是否可信。

AF-1 保留 SwiftUI 交互与现有数据身份，把对话、持久执行、审批、成果、记忆和主动跟进连成一个底座。OpenMuse 的 worker/计划/监控语义、OpenDots 的工作组织/审批入口作为检查输入；CopilotKit 通过小型事件与原生卡互通实验评估。框架采纳不成为功能验收的替代条件。

## 3. 页面与交互合同

| 入口 | 展示与动作 | 空/失败/等待行为 |
|---|---|---|
| 主对话 | 文本/图片输入、真实增量回复、任务/审批/成果卡；恢复上次会话 | 新会话可直接输入；未配置/未批准/受理未知分别解释；显示可执行下一步 |
| 待发队列 | 默认折叠摘要；查看、移除未发项、暂停、继续 | 不把未发项再次渲染成已发送；未知受理项不提供盲重发 |
| 活动/任务 | 目标、计划 revision、执行状态、等待原因、最近成果；暂停/恢复/取消 | 等用户给问题，等设备给打开 App 入口，失败给核对/修改入口；无限 spinner 不合格 |
| 审批详情 | 数据处理或动作详情、范围、目标、参数摘要、版本、期限、决定 | 关闭后消息/任务仍有入口；变更/过期先重取，不能批准旧版本 |
| 成果阅读 | 版本、来源、内容、更新时间；继续改稿 | 原对话与收件箱同 ID/version；加载失败保留入口，不显示虚构正文 |
| 记忆 | 已确认/候选分开，来源、适用范围、时间；更正/忘记 | 明确保存即确认；隐式抽取只候选；删除后能看到操作结果 |
| 跟进设置 | 目标、时间/时区或条件、频率、结束、预算、静默时段 | 创建时缺关键字段先问；失效来源/权限显示可修复原因 |
| 连接/设置 | 实际可用工具、模型处理方、许可撤销、版本/诊断 | 服务可达与曾取得完整真实回复分开展示；旧成功附时间/路由，不能保证当前可用 |

等待卡从主对话最多一次点击进入详情。发送/允许/拒绝等主动作点击后 500ms 内显示本地反馈，网络操作继续显示有意义状态。重复点按只核对同一命令；队列默认不占据大块主阅读空间。侧栏打开、关闭与返回不丢草稿；使用系统返回和辅助功能标签。

图片首版沿用已冻结视觉合同的数量、编码、字节和许可上限，实施时从现有合同读取，不在此另造数字。未发送图片可移除或替换，替换后重新核对 hash/许可；未批准不外发像素。历史能保存哪些图片内容、何时释放和如何删除由既有视觉数据契约展示，不承诺永久相册。

## 4. 对话、计划与持续责任

普通问答与可执行目标分别处理。目标包含用户目的、输入/范围、完成条件、预算/期限和停止条件；缺少任务定义所需信息时只问明确问题。一个 Goal 可以包含多个 Task/Run；一次回答结束不关闭持续责任。

计划保存步骤和 revision。用户修改要求使计划产生新版本；未执行步骤可调整，已发生的真实效果保留历史。若修改影响待批准动作，旧审批失效。进入执行前冻结当前范围，模型不能从网页、工具返回或先前文本扩大权限。

任务卡的进度以真实已记录步骤为依据，不生成无依据百分比。完成至少满足约定完成条件、所需工具回执及成果持久化；失败、等待、暂停、取消和 unknown 都是有解释和下一步的状态。取消表示停止后续动作并在安全点收尾，不能声称撤回已完成外部效果。

## 5. 工具、审批与设备边界

首版最小工具集合：给定公开 HTTPS URL 的真实读取、任务/成果读取与保存、明确记忆操作、受控日程写入。公网搜索只有实际接入且通过后才展示；没有工具时不凭模型旧知识回答实时问题。URL 读取需大小/时间/目标限制，不读取私网、凭据地址或用户未授权的数据。

每种工具登记参数 schema、读写属性、执行位置、所需授权、超时、幂等/核对能力、真实回执结构。provider 需要实际证明文字、结构化工具调用和图片能力；其中一种通过不证明其余两种。

模型处理许可、持续任务授权和一次具体写动作审批分别保留身份。写审批绑定账户/scope、actionID、目标、参数 hash、对象 revision 和期限。服务器持久化决定且重新检查后才能执行；本地“已点击允许”只是处理中。

设备动作只能在设备可用和系统权限允许时执行；云端生成待办不等于已写日历。回执含系统对象引用和相同 action/operation。若设备写成功而回执中断，先查同操作是否已创建对象，不能自动再写。权限拒绝保留计划和明确降级，不绕过系统授权。

## 6. 记忆与触发规则

记忆包含来源、确认状态、scope、revision 和可选有效期。更正产生新版本；任务启动冻结使用的记忆版本并可查看来源。删除影响后续任务与迟到抽取，已受理任务是否继续使用其旧快照须显示并允许暂停/重新计划，不能承诺删除自动撤回已发出的数据。

时间触发包含 IANA 时区、nextDue、频率、停止条件、每次执行预算与幂等 due key；相同 due 的并发投递只有一个逻辑 run。正常服务下到期后120s内受理，执行在声明预算内完成或明确终止。条件触发先保存基线和证据，再按明确条件判断；首次读取不能伪装成“检测到变化”。

首版监控公开文本内容变化；轮询频率/最大失败次数/退避/成本上限在创建时固定。到期唤醒与工作 checkpoint 在服务端持久化，App 前台计时器不是调度器。静默时段延迟提醒，不丢成果；暂停/结束后不接受新 due，已运行任务按明确取消策略收尾。

未知变化第一版交入 App 收件箱。AF-P 扩展通过前不承诺锁屏时即时推送云端变化。固定时间本地提醒不负责执行云端任务，也不证明云调度可靠性。

## 7. 原生智能 UI 合同

终版新增的[CGUI-1](../../design/conversation-generative-ui-spec.md)／[CG-A01–10](../../acceptance/conversation-generative-ui-acceptance.md)固定正文和六类卡中的table/bar/line／两种确定试算、局部状态和三类动作。它细分FINAL-G1的FQ质量门；不改以下六类领域身份。初片按现有toolStarted/toolResult、成果投影、operation/epoch/sequence映射并固定兼容codec。输入调节不发模型请求，显式跟进新turn／安全点接续；持久写走已有决定／effect权威。

| 类型 | 首版行为 | 权威对象 |
|---|---|---|
| choice | 选择缺失条件，提交后继续同任务 | input request / plan revision |
| form | 填明确结构字段，如时间/范围，显示错误与已提交状态 | typed action / revision |
| plan | 展示/修改计划与实际步骤进度 | Goal/Task/plan revision |
| approval | 查看并决定精确动作；重新打开仍显示同状态 | Approval/action hash |
| artifact | 打开成果并继续改稿 | Artifact/version/hash |
| comparison | 展示有来源的对比，选择后修改同计划 | Artifact/version + typed decision |

卡片公共字段采用主 spec 的 cardID、kind、schemaVersion、objectID、objectRevision、actionID 和 typed payload。未知 kind、过期对象或失配 schema 显示可读文本并重取状态；不能执行模型生成的任意脚本。卡片动画/关闭不改变持久审批。

### 四仓源码核读后的合同补充（2026-10-13）

依据[固定版本源码报告](../../research/copilotkit-four-repo-decision-update-2026-10-13.md)细化既有要求；以下是设计合同，不声称当前实现或修改冻结 HTTP 合同。

- **组件与能力。** 六种 kind 映射到编译内的 SwiftUI renderer、参数 schema 和允许的 typed action；客户端支持清单区分 kind/schema、展示能力与交互能力。增量参数尚未结束只可预览，完整校验后才读取权威对象并启用动作。模型选择组件不提供执行权限；陌生 schema/kind 降级为正文和原对象入口。
- **后台待决。** 展示类卡可持久保存引用；选择/表单/审批必须创建服务端等待记录，不能由 headless runner 虚构答案或依赖前台 hook。批准/拒绝和同任务恢复意图须持久关联；本轮拒绝不能通过新 toolCallID 对等价动作绕过。新参数/目标/revision 需要新决定。
- **执行与续聊。** 原 action 已消费但无真实结果时进入 unknown 并只读核对；有持久 receipt、但后续消息交付失败时只重交同结果。读取刷新错误不覆盖执行成功。两种失败给不同下一步，禁止通用 Retry 把两者混合。
- **计划进度。** 每步成功来自独立执行记录/回执；finish_task 不把未执行项批量标成功。任务完成仍由服务端按约定、成果版本和必需回执判定。
- **成果恢复与修改。** 消息/活动保存 objectID/version，重开读取真实内容与新访问链接，不持久保存短期 signed URL。请求携带对象与 generation，旧回复/旧 revision 不覆盖新对象或草稿；expectedRevision 冲突保留草稿，删除记录拦住迟到读取复活。继续修改在当前版本上创建新成果版本，保留来源和原会话。
- **调度与失败分类。** 持久 due occurrence 的去重键在完成后仍拦住晚到重复。一次 firing 内的恢复 attempts 与跨多次 firing 连续失败分别计数；等待用户/正常暂停不是失败。通知与轮询只提示重读状态，不承担调度权威。现有 monitor 的条件游标、静默、去重和退避要求继续适用。

落地先映射现有类型和数据库；新增字段/消息必须走兼容设计。OpenDots Pages 算法、OpenBot Approval/Work schema 及 OpenIntelligentUI registry 是候选参考，不另建第二套存储或执行状态机。

## 8. 状态与协议实现决策

权威复用现有领域服务和存储。UI 缓存、SSE 与通知只投影同一事实；不另建客户端调度器。实施时为 Goal/Task/Run/Turn/Approval/Effect/Artifact/Memory/Trigger/InboxItem 写现有类型→wire→存储映射，缺失端口按版本兼容扩展。

| 场景 | 必须满足的状态语义 |
|---|---|
| 点击发送 | 先持久保存本地意图和 operation；未批准不调用 turn/provider |
| 许可批准 | 持久许可 receipt 确认后继续原意图；弹窗 presentation state 不作为授权事实 |
| 服务受理 | 收到持久受理才显示已提交；accepted 不等于模型完成 |
| SSE/JSON | 根据 Content-Type 分别解码；完整帧/sequence 合并；重复不追加、gap 重取 |
| EOF/后台/超时 | 无 terminal 则未决；读取原 operation/turn/cursor，不新建 POST |
| Worker 接管 | checkpoint/成果提交核对当前 lease/fence 和权限 epoch；过期执行者不能提交 |
| 外部写结果未知 | 保存 effect 意图和核对入口；禁止自动重复执行 |
| 权限撤销/用户切换 | 新调用/提交核授权；旧 scope 的迟到事件不能进入新账户 |

遵循既有 v1 文字和 v2 图片身份；新增动作/状态先提交兼容映射，不重写冻结合同。一个客户端提交同一 operation 与 payload 只能生成一个逻辑意图；同 ID 不同 payload 是冲突。

CopilotKit spike 只做现有 runner→事件→Swift 解码→一张真实卡→持久审批恢复。对比事件完整性、取消/重开、适配复杂度和耗时后写采纳决定；不为试验安装新的生产依赖、迁移用户数据或付费 Intelligence。采纳/不采纳均不影响上述行为合同。

## 9. 验证接口与体验门槛

优先验证用户可观察行为：正常 App 入口＋已存在 HTTP/service 端口＋真实 PG/provider 回执；合成用例用于权限、幂等、sequence 和故障注入。没有真实执行条件时保留 NOT_RUN/BLOCKED，不以 fixture 改写真实结果。

沿用主 spec 的回显 p95≤150ms、短答首字 p95≤10s/完成 p95≤60s 体验目标；测量定义和样本数见验收脚本。恢复后 5s 内发起只读续接。性能失败与正确性失败分开定位，但未经显式范围修改都不能暗中降低放行门槛。

最终要求覆盖输入/许可、provider 字段与 terminal、服务持久化、真实数据库竞争、设备动作、原生卡、前后台与数据作用域。只测试外部行为和必要的协议边界，不增加逐行模仿实现的测试。

## 10. 本轮范围之外

任意电脑操作/浏览器登录、通用 MCP OAuth/工具商店、语音通话、多个 Specialist 独立学习、自动多 Agent、复杂空间编辑器、多设备实时协作和全量动态生成页面另立扩展 Goal。AF-1 只保证已登记工具可组合；不宣称覆盖所有 dot/Muse 功能。
