# AF-1 可执行验收与证据合同

版本：AF-1-G1，2026-10-13。细化 [AF-A01–18](../../acceptance/agent-foundation-acceptance.md)；不继承历史通过结果。本文与 [spec-details](spec-details.md) 和 [Goal 计划](plan.md) 配套，当前结果只记 [master-plan](../../status/master-plan.md)。机器映射见 [contract.json](contract.json)。

## 1. 统一执行条件

一次最终签收使用同一个候选源码 manifest、App build、协议版本和服务部署；测试中改动影响行为后，重验该行为及相关组合路径。S00 的准备检查不能替代最终 AF-A01 的真实安装/远端源码核验。

先写本次 run manifest：case IDs、测试主体/scope、源码/dirty hash、API deployment、protocol、App/包版本、设备与网络条件、时区、开始/结束时间、模型路由、最大模型调用数量、工具目标与结束条件。凭据、私人材料、原始设备标识不写入可提交证据。

只使用人工文本、无私密内容的随机图和获准的公开/受控资源；既有用户对话和未发队列不作为实验材料。正常 App 的新会话是入口，后台证据用只读诊断核对。无法取得配置、正常身份或批准的同版安装时记录 BLOCKED。

第一道探针最多一次短问答和成功后的追问；unknown 时不发追问，仅查询原 ID。每轮完整验收的调用上限在运行前固定，达到上限即停止，不为统计量无限调用。只读 GET 恢复不应引起新增 provider 调用；如实际增量异常，立即停止并核对。

## 2. 通过与失败的共同标准

| 检查 | 判定 |
|---|---|
| 真实模型 | 真实请求/路由记录、返回正文、明确 terminal、服务落盘与 App 可见结果对应；fixture/readiness 不够 |
| 一次发送 | 同 operation/request hash 仅一个逻辑 turn；重复按钮不重复 POST，断线先读原 ID |
| 一次副作用 | 同 action/effect 对应一个可核对目标；未知结果不自动再执行 |
| 任务完成 | 规定步骤、实际成果与终态一起提交；模型口头完成不够 |
| 多入口 | 原对话、活动与通知入口指向同对象/版本；不能各显示独立复制文本 |
| 范围与撤权 | 跨 scope、旧 revision、旧 lease/epoch 均不能提交或读取越界内容 |
| 证据缺失 | 未达到该环境层就 NOT_RUN/BLOCKED；不能标 PASS 后附注“尚未真机验证” |

FAIL 记录到具体段：输入→许可→turn 受理→provider→事件→存储→呈现；任务另含 claim/checkpoint/tool/effect/outbox。接口 EOF、超时、弹窗关闭和网络错误不表示真实完成或确定未执行。

## 4. 三条最终组合路径

### CP-01：研究交付与改稿

准备三条获准的公开文档 URL，不依赖尚未接入的搜索引擎；输入：“比较这三份资料，给出三条结论、一张对比表和可点击来源。先说明计划，完成后给我成果。”

1. 若缺关键范围，Agent 在原对话问一个具体问题；用户补充后得到持久 Task/计划。
2. 用户修改比较维度，计划 revision 更新，同 Task 继续。
3. 实际 URL 读取有回执；保存来源/时间、比较正文与 Artifact。
4. 云端已受理后离开 App；任务继续或明确等待，不能靠用户回来重发来完成。
5. 回 App 从原会话与收件箱打开相同成果版本。
6. 说“第二条结论补充风险”，形成新版本；旧版本和来源可追溯。
7. 在 AF-G5 最终运行中保存报告格式记忆后，新会话委托另一组公开来源报告，格式符合记忆，并显示来源。

通过：有用的报告内容、真实来源、执行/版本/恢复事实一致；AF-A07/08/11 与相关恢复/卡片成立。任一环节需要开发者CLI手工补写成果才能继续即 FAIL。把已有资料总结成报告与无人提供URL的自主搜索分别说明能力边界。

### CP-02：无人提问的变化跟进

准备可合法修改的公开测试页面和明确检查间隔/时区/结束条件。输入：“持续关注这个页面，内容变化后告诉我变了什么；没变不用提醒，到指定时间结束。”

1. 对话形成 Goal/Trigger，显示条件、频率、结束、预算和静默规则。
2. 完成 v1 基线读取；无变化的一次检查不产生新提醒。
3. 关闭 App、Mac；跨两个实际 due，服务端仍执行。受控测试把页面改成 v2。
4. v2 生成一个持久变化成果/收件箱事项；重复检查v2不新增同变化事项。
5. 受控来源错误后看到退避/下一次；恢复不重发旧变化。
6. 回 App 可读 v1/v2 依据和结果；暂停后跨下一个due无新增，结束后不自动恢复。

通过：AF-A12/13 的真实调度/去重/停止成立，并且用户不通过新提问触发工作。AF-1 验证 App 内查收；即时锁屏收到云端变化另按 AF-P 的 APNs 扩展验证。未接APNs在交付清单显式列限制。

### CP-03：本地日程与可控提醒

用明确测试日期/时区，输入：“在我的日历建一个20分钟的验收会议，并提前提醒我，先让我确认时间和日历。”

1. 对话形成 typed 日程动作，显示标题、起止时间、时区、目标日历和提醒。
2. 关闭审批再打开，信息不变；修改时间让旧卡失效。
3. 先拒绝一次系统访问，确认没有创建对象；重新允许后精确确认写入。
4. 日历中只有一个与回执相符的实际对象，重复点按不多建。
5. App后台/锁屏，实际已知时间提醒出现；点击返回原任务/日程详情。
6. 删除或更改这个测试日程时仅处理同对象，待发提醒同步更新；保留更改receipt。

通过：AF-A09/14/15 成立。跳转日历 App 或显示“已安排”文本不算写入。设备离线时云端只展示等设备，不宣称日历已创建。

## 5. 性能测量和稳定性

| 指标 | 起止定义 | 样本/门槛 |
|---|---|---|
| 本地回显 | 明确Send输入事件→同用户消息首个实际可见帧 | ≥20条人工文本；真机p95≤150ms；记录视频帧率与误差 |
| 决定反馈 | 点击允许/拒绝→本地“处理中/已暂停”实际可见 | 每条适用路径；≤500ms；不等待网络才反馈 |
| 首字 | 新意图首次显式Send→第一段真实assistant正文实际可见 | 许可已生效、无本地队列等待，固定既有路由；最终≥20个短问答样本p95≤10s |
| 短答完成 | 同Send→完整terminal正文已保存且可见 | 与首字同样本；p95≤60s；错误/超时也记录，不只选成功快样本 |
| 只读恢复 | 正常网络恢复/前台返回→发起同turn GET | 所有规定5s/30s/重开路径≤5s；完成恢复时间另记录 |
| 定时延迟 | dueAt→服务端job实际受理；受理→成果提交 | 至少两个实际due，受理延迟各≤120s；成果在创建时声明的任务预算内提交或明确终止；两段耗时分开报告 |
| 重复效果 | 同action/due/变更信号→真实目标或逻辑事项数量 | 正常、重复、unknown、接管路径均只一个；未知可保留，不能伪装成功 |

第一道探针和少量样本只能证明路径或得到初测数据，不证明p95。最终≥20模型样本属于发布验收运行，先固定调用上限和已有路由费用约束，不引入付费 fallback。若既有路由不能达到门槛，给用户实际数据并提出范围/路由选择；不静默将目标改成“尽力”。

可见帧以物理手机画面计时为准，诊断时间点用于定位；XCTest回调、CADisplayLink与Simulator事件不自动证明屏幕呈现时间。视频仅用人工材料，原始录屏/日志放忽略目录；精选可提交证据限合成内容并绑定hash。

## 6. 证据记录模板与放行包

每个case记录：`runID / caseID / goalID / sourceCommit 或 dirtyFilesSHA256 / apiDeployment / protocolVersion / appBuild / packageSHA256 / evidenceKind / environment / timezone / startedAt / endedAt / result / assertionResults / evidenceRefs / knownLimitations`。

真实模型另含：operation/turn/task、consent receipt、route hash、provider/model/request ID（若服务提供）、出站请求摘要、terminal、最终正文hash、模型调用增量。没有 provider request ID 时如实 unavailable，并以服务出站/返回关联说明证据局限，不伪造回执。

任务/效果另含：计划revision、claim/fence、checkpoint、approval/action hash、effect/外部对象引用、核对结论、artifact version/hash、trigger/due/run、outbox/点击目的地。原始响应凭据和私密payload不放入记录。

一个完整放行包包括18项结果及断言证据、CP-01–03记录、性能样本及算法、实际阻断/限制、源码/包/部署manifest。p95采用排序后第 `ceil(0.95*n)` 个观测值，不删除失败请求；失败单独计数且该运行不能达标。最终候选必需项有FAIL/NOT_RUN/BLOCKED时，AF-G5仍未完成。
