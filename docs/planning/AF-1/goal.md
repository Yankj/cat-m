# 当前 Goal 的执行定义

基础合同：AF-1-G3-UX1，2026-10-13；执行修订：2026-10-15。本文定义同一个 FINAL-G3 长期 Goal 的目标、依据、交付优先级和完成条件；不新建 Goal，不改变控制器状态，不维护第二份进度。实际进展仅见 [master-plan](../../status/master-plan.md)。详细拆分见 [plan](plan.md)，机器映射见 [contract](contract.json)。

## 总目标

**以唯一主仓持续交付可日常使用的 Swift 优先通用主动 Agent iPhone App：体验对标 Codex，能力对标 Dot。用户从自然对话交付目标，能在同一工作中查看和修改计划、引导执行、处理可找回的审批、查收有来源和版本的成果、管理记忆与持续跟进，并从原生提醒回到同一事项。普通问题直接回答；已受理的云端工作和时间/条件跟进不依赖手机或 Mac 在线。**

**长期终点为 FINAL-G3。基础 AF-G5 必须同一发布候选上 AF-A01–18、AF-U01–12 和 CP-01–03 全部通过；FINAL-G1 再通过 FQ-01–09、CG-A01–10 及七天真实日用；FINAL-G2 按 BP-01–08 原合同完成具名竞品配对并证明限定优势。G1/G2 同候选成立，源码、包、线上服务与证据一致，所有必需项无阻断缺陷，才完成 FINAL-G3。** AF-GD 是总 AF-G5 的必需部分；页面能看、安装成功、组件通过或 HTML 提案可点按均不能代替完整原生产品验收。当前运行 Goal 的简写目标按本文与对应验收合同执行。

体验具体落实为：单列正文优先的对话；合一的文本/附件输入器；轻量且不重复的队列；保留阅读锚点并能回到最新；可搜索、可返回且保留草稿的侧栏；真实状态驱动的任务/审批/成果卡；一致的原生详情与 sheet；浅深色、大字号、中文 IME、VoiceOver、Reduce Motion 和键盘安全区可用。诊断信息放次级入口，等待状态提供可执行下一步。

能力使用同一套 Goal/Task/Run/Approval/Effect/Artifact/Memory/Trigger/Inbox 组合。研究交付、变化跟进、本地日程三条路径不得各写一套特殊演示。模型文本和工具调用结束不自动成为任务成功；完成由持久成果、真实回执和规定检查支持。

## 2026-10-15交付优先级与启动规则

用户本次明确要求加速并行、当天完成交付、中午前提供一个版本验收；先更新本执行定义，待用户启动同一 Goal。时间均为 Asia/Shanghai。**最近硬交付节点为2026-10-15 12:00前，交付可启动、可完整点测一条工作路径的原生App阶段版及验收清单。** 不等待全部长期功能，不把代码编译成功当作版本交付。当天继续依据用户反馈修订，23:59前交付当日修订候选和关键路径的实现、实测结果与未闭合项。七天真实日用与具名配对仍按原合同完成，不因当天期限提前签收长期终点。

| 优先级 / 时间 | 可核对的交付要求 |

如用户启动已超过上述阶段时间，立即处理当前最紧迫交付，记录实际时间与逾期事实，不悄悄顺延、伪造准时结果或降低验收。真实模型、部署和新手机安装仍按具体既有授权处理；中午已获准的Simulator交付不得被这些外部阶段整体拖住。

启动后采用Root加三名内部Agent，按明确文件与端口分工；阶段任务完结即回收，不创建其他用户聊天：

| 负责人 | 中午前的职责与写入边界 |
|---|---|
| Root | 当前候选、App胶水与Xcode登记、唯一Simulator/Xcode操作者、同包验收、版本启动入口、master-plan、明确路径提交/推送及最终交付 |
| Agent A | 原生领域/应用服务/HTTP的原请求绑定、持久化、冷恢复与反例检查；不改Root的App胶水或界面 |
| Agent B | 本机维护API、有限工作执行/撤权与合成服务恢复；核对真实链路失败并准备具体修复清单；不修改原生源码或擅自请求生产模型/部署 |
| Agent C | 共享语义字号、容器/键盘/固定确认区和无障碍独立审查；默认先给Root可复现结果，只有明确分配的共享组件才写入，不逐页散改字号；准备用户点测检查 |

方法与效率约束：先画清楚用户意图→权威受理→持久事实→界面投影的链，再定位共同不变量。重复字号/裁切问题先查语义角色、Dynamic Type继承、容器约束、键盘安全区、当前滚动/光标与AX投影，使用共享机制修复；不以局部缩字、截断或QA覆盖掩盖。每个问题先复现、提出可证伪原因，再做一次最小修复与受影响回归。候选冻结期间其他Agent只读或处理不冲突文件；禁止边测边改、多人同时构建或用大量测试计数代替用户路径。

前20分钟须完成接管和首个缺口定位；同一故障20分钟没有新增证据，就记录假设/反例并调整排查，不盲目重跑。运行中按约30分钟里程碑说明实际产出、剩余与交付风险；必要工具等待期间也遵守会话及时更新要求。优先复用已通过且输入未变的检查，失败只做受影响复验。每片及时提交/推送已审阅明确路径，禁止混入其他owner WIP、未获披露许可的媒体、凭据或旧本地历史；没有用户路径变化不新开一片。

只有外部条件使全部可独立工作都无法推进、同一阻断连续至少三轮出现且确实需要用户输入/外部变化时，才按控制器规则标blocked。恢复后重新核对，不沿用旧阻断轮数。缺少真实模型只阻塞相应实测，不应阻塞可独立的Simulator交付。状态与交付结果仅写master-plan，既有日期证据保留。

## 范围与推进约束

1. 继续现有模型路由先验。具体包、最多两次短文本和正常 App 许可范围沿用已获用户授权；unknown只读核对原请求。未取得完整真实回复前不判模型通过或自动换供应商。
2. SwiftUI 为主交互层；局部 TS/其他技术以明确体验收益和版本化边界接入。OpenMuse、OpenDots用于需求与机制参考；不全量混合模板或默认改为RN/Web。CopilotKit接入以小型互通结果决策。
3. 云电脑只讨论、准备：现有Supabase先完善底座，新增计算预算0。后续公开网页/文件执行器与沙箱须另确认资源/供应商/区域；不部署或购买，不把试用赠额当永久免费。
4. AF-1必需项包括服务端独立调度、持久收件箱和已知时间本地提醒。远端未知变化即时APNs、云电脑、语音、多Specialist、任意MCP、第三方账户登录另列扩展。
5. 旧“今天首页＋会前就绪一周Demo”、飞书/微信/商家连接器及旧工期/现金估算是历史候选。会前/日程细节转为CP-03输入，不替换当前对话优先的通用底座，不新增账户、连接器或预算承诺。
6. 状态只维护master-plan；研究快照不被改写为最新安装或线上事实。总Goal保持进行中，只有全部同版必需验收通过才完成。

## 终版产品目标与当前执行 Goal 的关系
