# mimi（小咪）产品 Roadmap

2026-10-24 用户确认的产品与阶段范围；实施状态只在[主计划](../status/master-plan.md)维护。本文取代旧方案中的默认聊天入口、M0–M5 阶段编号和提醒后置安排。旧合同与日期证据保留，不因重定位而获得新的通过结论。

**帮妈妈把孩子的零碎事情接住，把日常安排与长期成长连起来。**

产品闭环是：理解交代 → 确认安排 → 跟进变化 → 记录事实 → 回顾调整。最终衡量妈妈少操多少心，包括交代一件事的步骤、纠正次数、漏事和重复解释，而不是聊天句数。默认进入“今天”；聊天、图片、语音服务于具体事情，输入能力存在不代表对应提取链已经验收。

## 里程碑与退出条件

| 阶段 | 用户能做什么 | 必须取得的验收证据 |
|---|---|---|
| **M1 先把一件事办清楚** | 默认今天；一句话在原界面生成可编辑草稿，确认后才成为安排；查看、调整、取消、完成、记录，退出重进不丢失 | 真实 iOS 构建通过；创建到完成与失败恢复流程跑通；保存成功才显示结果；“记录了”不写成“提醒了”。自动测试、原生操作与真实模型分别记录 |
| **M2 日常变化不用重新安排** | 自然语言改期、停一次；重复课程、单次例外、冲突提示、撤回；本机提醒作为日常可用门槛前置 | 改一次不误改整组；含糊先澄清；权限、时区、提醒状态明确；取消后旧提醒不触发；无权限不声称已提醒 |
| **M3 日常记录能帮助长期成长** | 目标拆为阶段尝试；安排、实际完成和观察关联目标；周/月回顾并调整下阶段 | 每条回顾能追溯记录；无数据不下结论；建议经确认才改变计划；不做孩子 KPI、评分或排名 |
| **M4 越来越懂这个家庭** | 复用经确认的习惯、偏好、约束和阶段变化；纠正、过期、删除 | 长期事实、临时情况、模型推测分开；一次请假不变长期习惯；纠正后不用旧值；孩子、账号之间不串用 |
| **M5 可靠主动，而不是频繁打扰** | 家庭云同步、多人分工、冲突处理、可靠通知；有依据地发现遗漏、变化和回顾节点；静默时间、频率控制和暂停 | 离线恢复不丢不重复；分工未经对方确认不算接手；提醒有依据、可行动，并解释为什么现在找你 |
| **M6 真实家庭试用，再扩场景** | 小范围验证上手、持续使用、错误率、打扰程度；核心育儿闭环有效后再扩家庭事务与妈妈自我管理 | 事先设定并达到试用指标；隐私、安全、删除、恢复流程通过，才讨论发布。择校等高风险且信息变化快的决策辅助后置 |

## 执行规则

同一时间只推进一个主里程碑，内部多 agent 按文件所有权并行。先关闭 M1 的构建与主流程问题，再进入 M2；后续方案和历史资产可整理，但不计为实施或阶段完成。部署、合并、发版单独确认；零新增计算预算、已有模型路线和凭据边界继续有效。

三条工作线贯穿各阶段：产品负责核心场景、界面、温馨文案与低负担交互；能力负责 AI 响应、结构化操作、记忆、提醒和同步；质量负责权限、儿童数据最小化、测试、性能和可观测性。每阶段分别标记 **代码／自动测试／设备验证／线上验收**；缺失、失败或跳过不折算为通过。设备验证注明模拟器或真机、候选 SHA 和包版本；mock/合成输入不能替代真实模型、数据库、系统效果或家庭试用。
