# Catpaw-m 通用主动 Agent 底座 spec

版本：AF-1，2026-10-13。当前交付进展仅在[主计划](../status/master-plan.md)，判定规则仅在[验收标准](../acceptance/agent-foundation-acceptance.md)。本 spec 替代旧单场景 Demo 的产品范围；v1 文字与 v2 图片 HTTP 合同、历史验收和上游来源保持其原有身份。

## 已确定的目标与边界

体验对标Codex，能力对标Dot：以连续对话、流式阅读、可操作执行卡和工作接续检验体验，以持久责任、记忆、主动触发与成果回流检验能力；公开行为作为参考，不声称内部实现或全量功能等价。

为个人提供一个能理解目标、执行任务、保存结果、持续跟进并在必要时请用户决定的通用底座。研究交付、变化跟进、本地日程是组合验收场景，使用同一套对象与执行机制。体验优先、Swift/SwiftUI 优先；局部 TS 或其他实现须以明确体验收益和协议边界接入。

现有模型路由先验证；失败须记录实际失败段后与用户讨论。不得自行更换供应商、放宽路由或引入付费 fallback。保留现有用户身份、数据、A1 图标、已选视觉体系和 MIT 归属。OpenMuse 用于运行机制参考，OpenDots 用于工作组织与审批参考，CopilotKit 仅在小型互通试验有收益后采纳。

云电脑首阶段用途已确定为网页调研与文件处理，不登录第三方账户。用户已选先用现有Supabase完善底座，新增计算预算0；托管执行器/沙箱的资源来源、供应商和部署仍待具体确认；先开发下表中已明确、可在现有工程实现的能力。新手机安装须以具体新包另行确认，旧安装许可不沿用。

## 用户能力与稳定需求 ID

| ID | 必须交付的行为 | 交互约束 |
|---|---|---|
| AF-R01 | 自然连续对话、追问、历史与恢复 | 一次 Send 对应一个持久意图；普通问题直接回答，不强制生成任务 |
| AF-R02 | 真正的流式文字与图片理解 | 本地回显立即出现；图片先预览、明确确认；真实像素与 provider 回执一致 |
| AF-R03 | 可找回的许可与审批 | 关闭弹窗、切页或重启仍能从消息/任务进入；显示动作、范围、参数版本、处理方 |
| AF-R04 | 对话形成目标、计划和执行步骤 | 条件不足时提一个具体问题；可补充、修改、暂停、取消；任务完成要有实际成果 |
| AF-R05 | 持久任务、失败恢复和副作用核对 | 原 task/run/operation 保持身份；租约与权限栅栏生效；结果未知先核对 |
| AF-R06 | 成果和待决事项回流 | 对话、活动/收件箱打开同一成果版本；内容可读、可继续修改 |
| AF-R07 | 可查看、更正、删除的记忆 | 区分候选与已确认；显示来源/时间/作用域；删除屏障阻止迟到结果复活 |
| AF-R08 | 时间和条件驱动的主动跟进 | 明确频率、结束条件、预算、静默时段；无变化静默，重复信号合并，失败退避 |
| AF-R09 | 原生本地动作和 App 外触达 | EventKit 写入经精确确认；设备不可用时等待；权限拒绝可降级；入口回同一事项 |
| AF-R10 | 受控智能 UI | 原生选择、表单、计划、审批、成果、对比六类卡；行为绑定真实 action 与对象版本 |
| AF-R11 | 日常可用的原生体验 | 输入区简洁；队列折叠；中文 IME、长文阅读、侧栏、大字号、VoiceOver 和前后台可用 |
| AF-R12 | 可追溯交付和能力诚实展示 | 源码/API/包/安装/证据可对齐；服务可达、真实回复已确认、失败分别显示 |

## 信息结构

对话是默认首页，恢复上次会话。侧栏提供历史、任务/活动、成果、记忆、连接与设置；返回路径可预期。队列摘要提供查看、暂停、删除和继续，默认折叠，不重复占用主阅读区域。

消息中的等待卡必须有下一步：确认处理方式、回答缺失条件、核对未知结果或查看失败原因。暂停本机待发消息与取消已受理云任务分别命名。连接诊断放在设置；首屏只展示简短且有事实依据的状态。

任务卡显示目标、当前步骤、等待原因和最近结果。成果阅读器显示版本、来源和更新时间。记忆页提供来源、更正与删除。能力不可用时解释具体缺失，不显示可点却无执行路径的按钮。

## 对象、权威与状态

复用现有 Goal/Task/Run/Turn/Approval/Artifact/Memory 对象，增加或映射 Trigger、Effect、InboxItem。这里定义语义；实施先映射现有类型和存储表，不另建一套客户端业务执行状态机。

| 对象 | 权威与必要字段 | 约束 |
|---|---|---|
| Turn/消息 | 服务端受理与事件；本地保存意图/草稿/cursor | operationID、request hash、epoch、sequence、明确 terminal；EOF 不等于完成 |
| Goal/Task/Run | 服务端持久记录 | scope、计划 revision、lease/fence、checkpoint、等待原因、取消与授权；聊天完成不等于任务完成 |
| Approval | 服务端授权记录；UI 是投影 | subject、action、target、参数 hash、revision、期限；失效授权不能被按钮重用 |
| Effect | 真实工具回执与核对结果 | 幂等键、执行位置、外部对象引用、结果；未知结果不得盲重放 |
| Artifact | 已提交成果版本 | task/run、version、内容 hash、来源引用；两个入口引用相同版本 |
| Memory | 版本化记录与删除屏障 | 来源、候选/确认、作用域、有效期；抽取 job 不覆盖较新更正或删除 |
| Trigger/InboxItem | 持久调度/提交事务 | 时区、nextDue、条件游标、去重键、预算；成果提交与通知 outbox 原子关联 |

消息语义：本地草稿/排队 → 等待许可 → 已受理/流式 → 完成或失败；受理不确定进入 unknown，读取原请求核对。任务语义：受理/排队 → 运行 → 等待用户、等待设备、暂停、失败、unknown 或真实完成。具体 wire 状态沿用现有合同，新增状态必须先做版本化兼容设计。

## 执行与协议边界

Swift 负责输入、原生卡、阅读、设备动作与本地缓存。Supabase 继续负责 Auth/Postgres 和适用的 API/持久存储。现有 TS/Deno 适配器负责模型、工具、任务与事件。独立 worker/沙箱是否增加由[云电脑提案](../architecture/cloud-computer-proposal.md)决定。

SSE 按完整帧和 sequence 解析，不要求每字一个事件。同 turn 重放返回 JSON 时按 Content-Type 解码。断线/后台恢复先 GET 同 turn 和事件 cursor，不重发原 POST；代际、scope、权限、撤权和租约校验必须在提交时生效。

工具登记 schema、读写属性、运行位置、授权要求、幂等/核对方式与返回结构。模型建议动作，实际执行依赖服务端授权和真实回执。设备动作不能假定手机长期在线。任意网页/模型生成的代码不直接成为客户端可执行 UI。

智能 UI 第一版限定六类版本化卡片，包含 cardID、kind、schemaVersion、objectID、objectRevision、actionID 和 typed payload。失配、未支持或过期卡降级为文本和可重新读取入口；动作提交重新核权限/版本。

## 可用性和完成条件

本地回显目标为真机 p95 ≤150ms；批准后有立即反馈；取消/等待状态可操作。短问答首字 p95 ≤10s、完整回答 p95 ≤60s 为首轮体验目标，须记录现有路由实测，达不到即作为性能问题讨论，不能用降低门槛暗中签收。5s/30s 后台和完整重开恢复原 turn，正常网络恢复后 5s 内启动只读续接。

真实模型、真实数据库恢复、真机体验、真实系统动作分别验收。测试数量、安装成功、readiness 和短标记不替代完整路径。通用底座完成须全部 AF-A01–AF-A18 必需项通过；云电脑 AF-C01–AF-C03 是单独待确认扩展，不阻塞先交可用底座，也不据此宣称完整 dot 云电脑已交付。
